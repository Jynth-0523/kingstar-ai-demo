# 金仕达 AI 投研与财富助手

用于现场展示的 B2B2C 双端 Demo（v0.5）。包含 Context Sufficiency、结构化证据核验、版本绑定审批、客户交付与 120 项验收测试。

当前使用合成资料、确定性解释模板及浏览器内状态。没有连接真实大模型、金融数据或生产身份认证。此代码不能直接处理真实客户资料或执行交易。

## 运行

需要支持 ES modules 的现代 Node.js，验证环境为 Node.js 24.19.0，无第三方运行依赖。

```sh
node tests/acceptance.mjs
node tests/demo-flow.mjs
node server.mjs
```

打开 http://127.0.0.1:4173 ，点击右上角“三分钟导览”，按提示完成补信息、证据核对、人工复核、报告交付与冲突演示。在当前 Mac 上也可双击 `start.command`。各场景进度、未保存输入与交付历史保存在当前浏览器，刷新可继续；浏览器禁用本地存储时会明确提示。重置只清空当前案例，并需在页面内确认。

## 流程完整性（v0.5）

- 页面顶部始终显示当前案例状态、原因与下一步操作。
- 首页顾问待办按补信息、核资料、答复、起草、复核、交付、客户确认等阶段筛选，点击直达处理步骤；仅汇总已打开案例。
- 草稿必须先提交复核；可批准或填写意见退回，修改后重新提交。
- 交付后由模拟客户确认阅读，才标记案例完成。
- 客户可以继续追问，由演示者填写顾问补充答复，形成新版本并按当前任务重新复核或交付；旧报告和回执保留。
- 输入改回已保存内容时，按钮立即恢复；退回后重新生成相同正文仍不能重提。
- 修改资料或正文会使旧审批失效，历史交付报告保留。
- 版本连续编号，重复交付与重复确认不增加记录。
- 八个场景独立保存；刷新、页面切换、场景切换后可继续。
- 部分场景进度损坏时保留可用案例、恢复损坏样例，并提供原始记录备份。保存失败时保留会话内进度并提示。

## 演示内容

- 三分钟分步导览；仍需手动填写信息并确认复核。
- 同额管理费测算：可调整金额和期限，冲突时暂停，明确排除其他费用。
- 顾问会前摘要与下一步沟通问题。
- 已交付客户报告可下载 HTML，或在浏览器中打印为 PDF。
- “调研与设计依据”页面保留五条官方来源、日期与对应设计取舍。
- 追问可手动选择继续一般解释，或转为个人持仓、用钱计划问题。转为个人情况后重新确认授权与画像，并检查持仓、证据和复核流程；系统不自动判断自由文本意图。
- 可一键填入示例问题、答复和客户信息；不自动提交、勾选授权或批准。已有问题和答复不会被示例覆盖。

当前交付范围为本地 Demo。之前 Sites 返回的托管域名存在解析问题，不作为演示入口。生产系统建设不属于当前完成标准。

## GitHub Pages 发布

发布配置已准备，尚未确认线上部署成功。预定仓库名为 `kingstar-ai-demo`；在账号 `Jynth-0523` 下成功部署后，入口为 `https://jynth-0523.github.io/kingstar-ai-demo/`。

1. 在 GitHub 创建公开仓库 `kingstar-ai-demo`，将本项目文件放入仓库根目录，保留 `dist/`、`tests/`、`package.json` 和 `.github/workflows/pages.yml` 的层级。
2. 打开仓库的 **Settings → Pages**，将 **Source** 设为 **GitHub Actions**。
3. 在 **Actions → Publish demo to GitHub Pages** 中运行工作流，或提交更新到 `main` 分支。测试全部通过后才发布 `dist/`。
4. 以 Pages 设置页或成功部署记录返回的网址为准，再实际打开网站核验。不要把预定网址当作已经上线的结果。

后续更新 `main` 会自动重新测试和发布。GitHub Pages 只托管静态网页；演示进度仍保存在访问者自己的浏览器。线上域名与本地地址的进度相互独立。

发布到 GitHub 的内容不需要 `.openai/` 中的旧托管标识，也不需要本机专用的 `start.command`。可在任何装有 Node.js 的电脑上运行 `npm start` 预览。

配置依据：[GitHub Pages 自定义发布工作流](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。
